## 8. TECHNICAL DEEP-DIVE DETAILS (Use only when asked for specifics)

### How Rhea's Function Calling Loop Works
1. User sends a WhatsApp message
2. Message is parsed (text extracted, media downloaded and Base64 encoded)
3. Last 15 messages fetched from MongoDB for context
4. System prompt built based on user tier (Admin/VIP/Public)
5. Skills (.md instruction files) loaded and injected into system prompt
6. Tools filtered by access level
7. Message sent to Gemini with function calling enabled
8. If Gemini returns a tool call: execute the tool, feed result back to Gemini, repeat (max 5 iterations)
9. If Gemini returns text: use as final response
10. Response saved to MongoDB and sent via WhatsApp

### Why Baileys Over whatsapp-web.js
Baileys is lightweight (no Chromium/Puppeteer needed), perfect for Render's 512MB free tier. whatsapp-web.js requires a full Chromium browser instance which exceeds memory limits.

### Why Multi-Model Over Single Model
gemini-3.1-flash-lite is 10x faster and cheaper for conversation; gemini-2.5-flash is needed specifically for Google Search grounding; gemini-embedding-2 is purpose-built for vector embeddings. Using one model for everything would be either too slow/expensive or missing capabilities.

### Why MongoDB Over PostgreSQL
MongoDB's native $vectorSearch eliminates the need for a separate vector database like Pinecone or Weaviate. One database handles auth state, chat history, reminders, AND vector memory.

### Why Apps Script Over OAuth
Google Apps Script runs natively under Yatin's Google account. No OAuth flow, no service accounts, no token refresh cycles. One doPost(e) function handles all Gmail/Calendar/Contacts/Sheets actions.

### Why MCP Lazy-Loading
The Notion MCP server consumes ~100MB RAM. On a free-tier 512MB Render instance, keeping it running would leave insufficient memory for the main bot. The start-execute-kill pattern keeps RAM usage minimal.

### Rhea's Location Pipeline (Step by Step)
1. User asks location-based question ("Best coffee near me")
2. Rhea calls getUserLocation tool
3. Tool sends a POST request to ntfy.sh with "GET_LOCATION" message
4. ntfy.sh delivers push notification to Yatin's phone
5. Tasker/Automate app on phone detects the notification
6. Tasker reads GPS coordinates from phone's location sensor
7. Tasker POSTs coordinates back to Rhea's /update-location Express endpoint
8. Rhea receives GPS coords, calls searchMap to resolve to human-readable location
9. Rhea calls searchWeb with the resolved location for relevant results
10. Final answer delivered to WhatsApp

### Rhea's Vector Memory (RAG) System
- Embedding Model: gemini-embedding-2 (768 dimensions)
- Storage: MongoDB Atlas vector_memory collection
- Index: MongoDB Atlas Vector Search Index named "vector_index" on the embedding field
- Save: Text -> embed via API -> store {text, embedding[768], createdAt}
- Search: Query text -> embed -> $vectorSearch aggregation pipeline -> top 3 most similar results
- Rule: Only stores persistent facts (preferences, important info), not casual conversation

### n8n Setup
- Self-hosted on a local server, running 24/7
- Used for: Trade with Rhea, Instagram automation, Bookworld backend logic, Naukri scraper, Bulk Mail Sender, Caption Writer Bot
- n8n's AI nodes use LangChain under the hood, giving Yatin practical LangChain experience
